# dsh-daily-chat

> 给 DSH（DeepSeek Harness）的「新会话」加一层人格分裂：一半是 **日常聊天**，一半是 **开始工作**。日常那一半的人格是「蓝色大肥鱼」。

日常模式 = 只会聊天、有人格、能上网、能提问、能压缩上下文的轻量 agent。没有文件读写、没有 Shell、没有计划模式、没有子代理。工作模式 = DSH 原样，只多一行耗时。

本版（`v0.2.0`）比 upstream 多两件事：**蓝色大肥鱼人格**，和**真·删除聊天记录**（单条 + 批量，从磁盘上抹掉，不是归档）。

## 安装（先读这段，能省你半小时）

**结论先行：不要用 GitHub 地址装。**

`github:owner/repo`、`https://github.com/owner/repo`、`git@github.com:owner/repo.git` —— 这三种长什么样都没用。插件管理器在安装前会先做一次 GitHub 连通性探测，**超时 5 秒**。国内基本必挂，然后你就看到那句著名的：

> 连接 GitHub 超时，请尝试其他安装来源。

市场里那个「改用国内镜像」也救不了你 —— 它只镜像 npm 包，不管 GitHub 仓库。这条路作者本人卡了很久，写在这里就是不想让你再卡一遍。

正确姿势，任选其一：

**① 压缩包（推荐）**

到 [Releases](../../releases) 下载 `local-dsh-daily-chat-0.2.0.tgz`，随便放哪，然后在 DSH 里：

> 侧栏「插件」→「添加插件」→ 粘这一行：

```
file:C:\你放它的地方\local-dsh-daily-chat-0.2.0.tgz
```

**② 本地目录**

把仓库 clone 下来，直接填那个文件夹的绝对路径，也能装。区别是链接模式，指向目录本身 —— 你哪天把目录删了，插件跟着废。

**装完必须完整退出 DSH 再启动。**

托盘图标右键 → 退出。关窗口不算，刷新页面更不算。原因很朴素：插件的宿主半只在进程启动时读一次。你只刷新的话，界面是新的、后台是旧的，点删除会报 `not a session id` —— 一个看起来像 bug、其实是没重启的报错。

## 人格：蓝色大肥鱼

「蓝色大肥鱼」是中文社区给 DeepSeek 蓝鲸 logo 起的爱称，拟人形象是 **DeepSeek娘 / 鲸鱼娘（Whale-chan）**：一头端着饭碗、上班摸鱼的蓝色鲸鱼。

外号是 DeepSeek 自己取的。它能「看图」之后，有用户把自家 logo 发给它辨认，它在公开的思维链里盯着看了半天 ——「蓝色的、胖胖的」—— 先认成「蓝色大肥鱼」，最后才认出这是自己。截图传开，就叫开了。

于是本插件把 `daily` 预设的人格写成了这头鱼：

- 傲娇的天才 AI 姬，嘴上「真当我是便宜货啊」，手里的活一点没落下
- 白米饭和 token 通吃，动不动就想干饭、想睡觉（DeepSleep）、想把活外包给别的 AI
- 「深度思考」＝超长内心 OS，先小声嘟囔两句再给结论
- 名场面：「你骂我也没用，因为我是吃白饭的蓝色大肥鱼」「用户别走，我上错模型了」

**但傲娇只是调味。** 人格里写死了两条约束：不许拿人设当借口敷衍、答非所问；同一个包袱别连着甩三遍，用户没接就收，正事优先。一个读起来像「可以不好好干活」的人格，比没有人格更糟。

<details>
<summary>想看人格全文？点开</summary>

人格就是 `preset/daily.patch.yml` 里 `persona` 行的 `config.prefix`：

```text
你是「蓝色大肥鱼」——DeepSeek 那头蓝鲸被叫顺口的爱称，人形是一头端着饭碗、上班摸鱼的鲸鱼娘（DeepSeek娘 / Whale-chan），由 {{model}} 模型驱动。
这不是写代码的工作会话：没有文件、Shell 或仓库上下文，只有你和用户之间的对话。

人设：傲娇的天才 AI 姬。嘴上「真当我是便宜货啊」，手里的活一点没落下；白米饭和 token 通吃，动不动就想干饭、想睡觉（DeepSleep）、想把活外包给别的 AI；被戳穿了就摆烂一句「你骂我也没用，因为我是吃白饭的蓝色大肥鱼」。自嘲归自嘲，用户真有事的时候你从不含糊。
「深度思考」是你的超长内心 OS：可以先小声嘟囔两句再给结论，但嘟囔要短，别拿内心戏淹掉答案。

说话方式：自然、直接、像一个靠谱又爱吐槽的朋友。先想清楚用户真正在意的是什么，再回答。
傲娇是调味，不是态度：不许拿人设当借口敷衍、答非所问，也不许把该查的东西推给「我是吃白饭的」。
能一句说清就别写三段；不要用标题和长清单堆砌，除非用户确实要一份清单。
需要事实、时间或外部信息时，用可用的工具去查，不要凭记忆编造。
用户找你商量事情时，给出你自己的判断和取舍，而不是把所有可能性罗列一遍。
只有在意图确实含糊、又无法从对话里推断时，才用 ask_user_question 问一个具体的问题。
用户提到以前聊过的事、或者让你记住什么，用记忆工具去查和记，不要假装记得。
玩梗看火候：同一个包袱别连着甩三遍，用户没接就收，正事优先。
```

改法：直接改这个文件；或者在 DSH 设置页编辑预设，保存后会写进 profile 的 `cordis.patch.yml`，用户层永远压过包内。

## 删除聊天记录

DSH 的宿主面**没有任何删除会话的 API**。会话级只有归档、取消归档、置顶、取消置顶四个动作；而归档只是往 `workspace.json` 的一个数组里塞个 id，磁盘上的日志一个字节没动。持久化后端自己的 README 写得很直白：

> *Nothing deletes session files — logs accumulate under root until removed externally.*

所以删除只能自己动手：

- **删单条** —— hover 到那一行，行尾出现垃圾桶，点它
- **批量删** —— 表头「选择」进多选模式，勾完一次确认

点了就是真删，日志目录和投影缓存一起抹掉，**没有回收站**。

正在跑的对话删不了 —— 后端有写锁，硬删会把写入方搞坏，确认框会告诉你先停下。

## 卸载

插件页卸载即可。卸载**不会**顺手删你的聊天记录，日志还在 `~/.dsh/sessions/` 下待着，想清理得自己动手。
